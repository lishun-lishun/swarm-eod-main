## 比赛实际调用链

`src/swarm_rescue/solutions/my_drone_eval.py` 返回 `FinalCompetitionDrone`。其 `control()` 先通过 `FusionRescueDrone` / `SictRescueDrone` 的 `_control_body()` 完成合法传感、融合地图、炸弹认领与任务动作，再由 `_control_with_safety()` 对指定空载探索/走廊状态实施预测安全过滤。携弹抓取、推/拉姿态及终端处置仍走旧链路。

`SictRescueDrone._choose_bomb()` 在合法发现的 `self.know.bombs` 中按地图 Dijkstra 成本排序；`Knowledge.claimed_by_better_peer()` 与无线 `claim_cost` 比较的是**像素量级路径成本**。V4 ETA 仅改变本机候选排序，旧像素成本继续用于认领报文。`_velocity_to_command()` 的 V4 模型分支仅用于空载、非精细、`EXPLORE`、LiDAR全部有效距离大于90px且无近距可见无人机的帧；其余仍用原飞控。最终安全层只执行一次。

## 官方参数核验

源码 `simulation/utils/constants.py`：LiDAR 181射线、230px；语义35射线、130px；通信半径180px。空载官方物理标定 `reports/dynamics_identification.json`：每控制帧 `v[k+1]=0.95v[k]+0.5729312289729012u[k]`，10个Pymunk微步，约11.46px/帧稳态上限。载弹初值 `0.95/0.19` 是待辨识候选，绝非已验证真值。最终动作的平移合力受二维单位圆约束。

## 独立开关及安全边界

| 开关 | 默认 | 作用 |
|---|---:|---|
| `V4_PREDICTIVE_ASSIGNMENT` | 0 | 本机 ETA 排序与任务切换滞回，保留旧无线像素认领协议 |
| `V4_MODEL_EMPTY` | 0 | 开阔空载探索下的离散模型速度推力 |
| `V4_MODEL_LEGAL_OBSERVER` | 0 | 与空载模型同时启用时用合法模型/里程计速度估计替代原平滑里程计反馈；实测未通过 |
| `V4_CARGO_IDENTIFICATION` | 0 | 载弹合法运动数据的影子辨识，不改变动作；只在GPS、里程计有效且远离障碍和队友时更新 |
| `V4_MODEL_CARGO` | 不存在 | 尚无获准载弹模型；影子辨识绝不自动接管控制 |

现有 Map06/Map08 漏探目标的可视站位在融合图中多处不可达；简单让本机自由覆盖队友障碍曾使 Map08 从8/10退至6/10。因此 V4 初期不更改地图融合、抓取或携弹终端控制。全局缩小中心到达阈值曾使 Map09 从10/10退至7/10，V4 不采用该方案。

## 验收原则

以同一固定炸弹布局、NO_GPS_ZONE 与 NO_COM_ZONE、官方 Launcher/Pymunk、同引擎 seed 作 A/B；依次比较满拆地图数、总官方处置数、原10/10地图回归、官方分数、时间与健康。单元测试或模型 RMSE 不能替代官方成绩。未通过前保持开关默认关闭，不生成新提交 ZIP。
