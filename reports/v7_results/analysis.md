# Swarm-Rescue V7 官方 Pymunk 实验与接收结论

## 结论

以 `v6/evidence-based` 的 `498b56448a8a72b68092a5fd9250f5c65b1c3737` 为基点，已在独立分支 `v7/gateway-egotrail` 接入压缩包提供的五个 V7 模块及其可独立开关的控制调用链。压缩包 26 项测试在接入前、接入后均通过；与 V4/V5/V6 集成测试合计 72 项通过。所有 V7 主动开关默认关闭。

**本轮接收源码作为实验原型与只读观测，不接收任何主动 V7 开关作为比赛默认策略。** 原因是官方消融中 Gateway 虽实际抵达 Map06 的 43 个、Map08 的 26 个网关，却没有观察到原漏弹；Map08 还从 8/10 降为 7/10。Map09 seed862 的 6 号携弹机短退路动作仍为 9/10，官方分和健康略降。稳定比赛包 `artifacts/latest_upload/team006_final.zip` 保持原 SHA256 `02193D3B368AE2471FD163BDB090428FAEB02664DAFB3AD729F4141BD21FD6E3`，没有替换。

按用户交付要求，将稳定包逐字节复制为 `artifacts/v7_delivery/team006_final.zip`，官方提交检查通过，并将 ZIP 内源码安装到隔离环境完整重跑十图固定布局 seed861。结果同为 93/100、平均 83.78 分；详见 `reports/v7_results/submission_report.md` 和 `reports/fixed_suites/v7_packaged_all_e861/summary.json`。

## 失败定位

- **Map06 漏探**：影子基线的 2、3 号弹未发现，1 号弹已抓取但未处置。主动 Gateway 多出的官方处置是 1 号弹运输链路成功，2、3 号仍未发现；最近实际抵达的网关距 2、3 号弹约 229/279px，9 号机的真实 35 射线记录未覆盖对应弹位。不能把 +1 处置归因于语义补盲。
- **Map08 漏探与退化**：0、3 号弹在基线和 Gateway 主动版都未发现；最近抵达网关距它们约 667/402px，真实 35 射线记录仍空。Gateway 主动版使 8 号弹直到第 4509 步才抓取且未处置，基线在第 1442 步抓取、第 3661 步官方处置。延后网关后该弹恢复早抓取，但另有已抓取弹最终未处置，说明还存在运输链路耦合；本轮没有足够证据接收 Gateway。
- **Map09 seed862 无 GPS 载弹**：6 号机第 5010、5360 步路径瞬时清空并进入原脱困，其他时刻约 95 个路径点却常停在首航点。只盯连续空路径会漏掉真实停滞，故只读判据改为持续无进展；但 426 帧主动短退路没有增加官方处置，还降低健康/分数。局部退路不能解决全局返航或中心连通性。
- **Map07t4**：默认策略 seed861 为 8/10；本轮只保护基线，没有对中心语义假到达作新的主动修改。

逐弹离线生命周期、网关计划/抵达、退路候选/动作、官方处置事件在 `reports/v7_results/failure_trace.json`。其中真值弹位只由独立赛后评估器读取，比赛控制器不使用。
