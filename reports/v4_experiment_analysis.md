# PTC-MDC V4 官方仿真实验与接收决策

## 实验环境

基点为本地缓存 `origin/main` 的 `977afba038e327ee861e0bbef6311abfc690c084`，开发分支 `v4/ptc-mdc`。远程 GitHub 在本环境代理连接失败，无法核验在线 `main` 是否更新。实验由 `tools/run_fixed_suite.py` 调用官方 Launcher/Pymunk、10架无人机、`config/zones_location.txt` 固定炸弹布局，并保留地图原有无GPS和无通信区域。861种子的四个对照使用相同比赛策略源码哈希 `2076b46983ca228ac1db2db229c4d7a81d2442482cee67947364452088366cc8`，仅通过独立开关切换策略。

ETA使Map08、Map09丢弹；Map08虽有10次抓取，却仅实际处置7枚，两架无人机在4864、4999步才抓取并随后卡在携弹返航，`stuck` 从63增至91，碰撞伤害事件从38增至86。空载模型使Map09、Map07丢弹；Map09有10次抓取但 `stuck` 从56增至125，说明开阔空载控制的时间扰动仍影响后续运输链路。两个单模块均拒绝作为默认策略。

组合方案的 Map06 从7增至8枚，8次抓取全部处置，`stuck` 从93降至36。该增益发生在运输成功率，不是多发现一枚炸弹。组合的 Map07 与 Map09 均保持满拆，但分数分别下降1.5、2.6。因果机制尚未由逐帧轨迹证实，不能仅按相关性解释。

## 载弹影子辨识

`V4_CARGO_IDENTIFICATION=1` 仅收集合法里程计上一控制区间位移、当前最终施加推力、GPS有效性、地图净空及邻机观测；它不改动作。种子861 Map09仍为10/10、85.8分，Map06仍为7/10、58.1分。Map09训练更新2078组，另有530组留出验证，各机留出RMSE约0.33–0.47 px/帧，参数离散明显。该模型没有获得控制授权，载弹推/拉和处置逻辑继续使用稳定旧版。

## 暂存判断

种子862五图配对：基线为43/50、平均69.12分，组合为42/50、平均69.40分。Map09从9/10降至8/10；Map06、Map07t4、Map08、Map07拆除数不变。按优先拆除数的验收规则，**拒绝原组合方案**。Map07的组合完成步数从3863降至3012，但不能抵消Map09丢弹。完整原始结果在 `reports/fixed_suites/v4_baseline_subset_e862/` 与 `reports/fixed_suites/v4_combined_subset_e862/`。

种子862 Map09 又以 `CARRY_TRACE=1`、`POSE_TRACE=1` 复跑组合，复现8/10、65.3分。无人机6在最后360帧持续处于无通信区，中心路径代价约2318→2280 px，末帧路径为空，位置约(-284.5,174.9)→(-266.1,166.0)，没有形成有效返航推进；基线同机也未成功处置。组合额外失败来自无人机3：第5084步才认领末弹、5110步抓取，比赛5400步结束时它尚处携弹路径上。它在基线只承担1次抓取，组合承担3次。由此可直接观察到任务分配改变了末段运输负荷；不能声称是空载速度跟踪误差单独导致丢弹。逐帧携弹轨迹和合法传感状态保存在 `reports/v4_failure_trace_Map09_e862.json`，完整逐帧位姿在 `reports/fixed_suites/v4_combined_trace_Map09_e862/Map09_e862.json`。

空载模型反馈另以合法速度估计器、上一帧最终动作对齐进行独立试验：种子861 Map09降至7/10、58.2分，Map07保持10/10但降至84.6分；Map09有10次抓取、仅7次成功处置，说明末端运输链路继续退化。该估计器分支由 `V4_MODEL_LEGAL_OBSERVER` 单独控制，默认关闭。

保持所有V4策略开关默认关闭；不覆盖稳定提交ZIP。Map06/Map07t4/Map08仍有未处置任务，未达最终目标。原始官方JSON与判断字段见 `reports/fixed_suites/`、`reports/task_assignment_ablation.json`、`reports/flight_control_ablation.json`、`reports/all_maps_v4_summary.json`、`reports/cross_seed_v4_summary.json` 和 `reports/dynamics_calibration_v4.json`。
